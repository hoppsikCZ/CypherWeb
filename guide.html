01 / Reversible transformations

What is a cipher?

A cipher transforms a message using a rule, often controlled by a key. The intended reader uses the rule and key to reverse it. These classic examples work with English letters and preserve other characters such as spaces and punctuation.

Caesar cipher

The Caesar cipher shifts every letter by the same number of positions in the alphabet, wrapping from Z back to A. For example, a shift of 3 changes HELLO to KHOOR. To decode, shift by the same amount in the opposite direction.

There are only 26 possible shifts, so trying each one quickly reveals the original message. It is useful for demonstrating substitution, not for protecting sensitive information.

ROT13

ROT13 is a Caesar cipher with a fixed shift of 13. Since the English alphabet has 26 letters, applying ROT13 twice returns the original text. The same operation encodes and decodes.

It can obscure text from a quick glance, but provides no secrecy: anyone can reverse it immediately.

Atbash

Atbash replaces each letter with its opposite in the alphabet: A becomes Z, B becomes Y, and M becomes N. This mapping reverses itself, so applying it a second time restores the original.

Atbash has no key and is easy to reverse. It is a historical substitution method, not modern encryption.

Vigenère cipher

The Vigenère cipher uses a repeating keyword to shift each letter by a different amount. With the key LEMON, ATTACK becomes LXFOPV. The keyword determines the sequence of shifts.

It is more involved than a single Caesar shift, but repeated keys and patterns can still reveal the message. It is not secure by modern standards.

Rail Fence cipher

This transposition cipher writes the message diagonally across a chosen number of rows (rails), then reads each row in turn. With 3 rails, the letters zigzag down and back up before being read row by row.

It rearranges letters rather than replacing them. The rail count is the key, but the small number of possible arrangements makes it unsuitable for real secrecy.

02 / One-way fingerprints

What is a hash?

A hash function turns data of any length into a fixed-size digest—a kind of digital fingerprint. The same input always produces the same digest, and even a tiny change to the input produces a very different result.

Unlike a cipher, hashing is one-way: there is no key to decrypt a digest back into its original message. Hashes can help check data integrity, but plain hashes are not suitable for storing passwords.

SHA-256

A member of the SHA-2 family that produces a 256-bit (32-byte) digest. It is widely used for integrity and digital-signature systems. It is not a password-hashing function by itself.

SHA-384

Another SHA-2 function with a 384-bit (48-byte) digest. It uses the SHA-512 family design with a shorter output.

SHA-512

A SHA-2 function that produces a 512-bit (64-byte) digest. The longer output does not make it interchangeable with a password-hashing scheme.

SHA-1

SHA-1 produces a 160-bit (20-byte) digest, but practical collision attacks are known. It is included for legacy compatibility only and should not be chosen for new security-sensitive uses.

MD5

MD5 produces a 128-bit (16-byte) digest. Practical collision attacks make it unsuitable for security, including verifying authenticity or protecting passwords. It is sometimes encountered in legacy systems and non-security checks.

For password storage, use a dedicated, deliberately slow password-hashing algorithm with a unique salt, such as Argon2id, scrypt, or bcrypt. Never store passwords as plain SHA digests.
